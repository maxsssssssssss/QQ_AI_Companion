## 短延迟补充与真实发送边界

原来5–60分钟的补充候选仍先后受到原生preflight和route guard的45分钟空闲门槛限制。只改其中一处不能兑现短补充。

现在只有确认过完整父回复、同一交流、身份与入站epoch一致、父轮仍在5–60分钟候选范围内的补充，才在现有原生检查作用域中使用5分钟短避让。普通新话题仍为45分钟。仍需通过允许时段、暂停/忙碌、话题关闭、一次补充、每日尝试与Guard检查，不创建新调度器。

固定AstrBot 4.29.1 / PrivateCompanion 6.7.0 / Guard完整隔离链验证：父被动回复确认后约10分钟，可经候选池与原生tick产生补充；2分钟、新入站改变epoch、普通新题仅10分钟时均不产生评估或发送。兴趣表达后同机会的结果无需额外等5/45分钟，但两个独立发送批次各计一次尝试。上述时间是隔离时钟和合成OneBot验证，不承诺线上恰好10分钟发消息，也不冒充真实QQ。

## 内容修订、真实失败及误伤修复

旧实验最终请求的检查区分了测试夹具缺口与真实模型错误：旧构造机会有的没有当前日期或真实已确认主动正文，而真实鸟类资料的主体明明在工具结果中，仍被模型转述错误。候选显式提供真实时间、最近8条已确认主动完整正文和原生近期上下文；已确认只表示说过，不证明台词中的经历真实。

候选在同一个Agent、Provider、工具上下文中最多进行两次发送前修订。R5在首次修订通过且涉及来源事实或已有确认主动历史时，把剩余一次用于完整正文校核；协议/证据错误也共用这个上限，不额外叠加第四次生成。所有实际SDK续调照常消耗原144次/日限额；初始skip/defer不为了提高发送率再调用模型；无来源事实且无确认主动历史的新观点保持一次修订。未发送草稿不进入用户可见历史。

程序核对原始控制行、来源是否来自本机会或被选口袋的真实工具回执、引文是否是对应来源的连续原文、本地显式算式、内部审计JSON，以及有限的无依据具体自身经历模式。模型仍负责语义、观点是否真正新增、主体/限定/研究条件与原文是否相符；引用片段存在与自查字段不是语义真实性证明。

R3曾新增逐字正文关联及任意数字覆盖硬门槛，真实复验发现正常新观点被误拒，以及“一个数字”“一个名额”被误当外部数量。这些原输出保留。R4取消这两项硬门槛：程序直接绑定实际最终正文SHA；模型写的关联片段不逐字时明确记录inexact，不伪造匹配证明。外部来源和连续原文核对仍保留。缺省的自身经历自报字段保持缺省，不自动写成已经验证为false。

内部审计JSON若出现在可见正文中进入现有一次纠正，持续回显则拒绝；正常技术JSON不受此规则限制。兴趣表达若包含内部JSON或明确的无依据具体经历，不发送该前缀，后续工具仍可静默继续。确认正文中的明确原生偏好可提取，但确认送达不认证经历；原生摘要仍保留原文来源及不把模型自述升级为用户事实的约束。

## 联合验证发现的发送适配缺陷

第一次真实固定宿主联合验证发现，原生纯展示限制会把完整主动正文裁为全组260字、3行或4句，造成半句话及末尾偏好丢失。候选仅在现有主动清理作用域解除这些展示截断，保留原生收件人、内部指令、Provider错误及未执行转述承诺检查，并把长尾纳入原生检查。

同时移除清理单个模型气泡时再次执行V4兜底的耦合，避免2泡变4泡；最终Guard仍只执行原有一次分段。固定宿主长单泡353字符/1泡、长标记374字符/2泡均完整确认，账本=模型历史，尾部偏好可提取；Provider错误与长尾转述承诺为0发送、0偏好。这是T2，不是QQ实测。


最终原生联合复验又定位到残缺控制标记：原生本地审查使用500字单行预览，删除“我想了半天”一类动机表述时误吃分段标记尾部；后续整体清理还会再次删除或压平边界。修复仅在原生解析出的完整气泡内分别执行原生清理，并保留内部块删除、动作检查和拦截结果。无法可靠映射的长正文改写取消发送，不恢复被删除内容，不把500字预览或260字清理截断当成完整正文。

最终48项原生组件、4项Guard定点和19场景完整固定原生链通过。700余字三泡正文完整，长尾硬拦截零attempt/历史；实际故障完整原文另在固定宿主重放，确认3泡，账本与唯一assistant历史逐字一致，动机清理仍生效。180条真实历史输出的离线回放中137条适用：135条不改、2条按原生无来源近期动作规则清理，43条非send或协议无效不适用；没有残缺标记。该离线回放没有重建所有原工具上下文，不能把那两条变化归为线上内容损失或宣称全部泡数不变。

以上均未发送真实QQ。原生清理及其全文/片段映射是兼容适配，不修改固定PrivateCompanion源码。2–4秒间隔、打断、unknown不重发、确认前缀历史保持由现有Guard负责。

## 待分享内容与研究期限

状态继续存放在现有主动控制 SQLite 数据库中，不新增事实主库或调度器。待分享内容保留 `created`、`updated`、`last_progress`、`expires` 和修订号，读取、选择、原样保存均不会刷新有效期。

|行为|期限处理|
|---|---|
|新建未分享记录|最多保留三天，调用方可以指定更早到期|
|读取、选择、原样保存|不续期；原样保存不增加修订号|
|普通草稿改写或换措辞|可以更新内容，但不延后原到期时间|
|明确研究进展|调用方提供进展标记，状态层再检查内容、进展或来源变化，才可续期最多三天|
|同一记录持续研究|从首次创建起最多三十天，不能靠连续保存越过上限|
|已过期、已丢弃或已分享|不因重新读取而恢复为待发送|

调用方对“有进展”的判断也有限制：新的实际工具资料需有变化的内容摘要，并有进展说明；本地创作或假设可以继续，但需由同 Agent 的检查说明具体新增内容。普通旧分享只换措辞不能续期。内容摘要变化只提供结构证据，不能证明语义上一定有新发现；创作进展仍含模型判断。

迁移仅增加 `last_progress` 列。旧记录按首次创建时间保守初始化，不能把此前可能由重复保存更新的时间当作真实进展。容量沿用现有配置：活动记录满额时拒绝新增，不静默删除尚未分享内容；终态记录按既有十四天保留与最多三倍活动容量的尾部上限清理。

来源时间独立于草稿期限。`observed_at` / `fetched_at` 表示取得资料的时间，不是事实发生或文章发表时间。旧资料超过三天会显示 `aging`，仍可按原日期与范围使用；仅来源明确过期、撤销或时间无效时不可使用。续期研究不能改新旧来源的观察时间，也不能撤销原有的来源撤销标记。重新取得同一正文可以更新检索观察，但本身不证明研究产生了新结论。

重启后保留口袋与修订号，所有记录仍标记需要重新评估，不直接发送保存草稿。分享状态依赖 Guard 的实际确认结果；未确认或部分送达不能自动认作整条发现已经分享。

实现入口：`integrations/phase3_runtime/autonomy_state.py`；调用方：`autonomy.py::save_progress`。确定性验证覆盖跨日续期、原样保存、重启、旧表迁移、三十天上限、容量、来源过期及撤销。原状态测试 28 项、专门 TTL 测试 14 项及计算测试 18 项的已完成记录见私有测试证据；这些计数不另算成真实 QQ 测试。

## 同 Agent 的本地精确计算

现有 Agent 注册一个 `autonomy_calculate` 工具，供模型核对自己准备表达的算式。它不调用模型、不联网、不发送 QQ，也不修改用户记忆。

- 只接受数值、括号和 `+ - * /`；不使用 `eval`，拒绝变量、调用、幂、取模等额外语法。
- 表达式最多 256 字符、AST 最多 64 个节点、嵌套最多 16 层，数值及中间结果另有大小限制。
- 使用 `Decimal` 解析数值字面量，再用 `Fraction` 计算；返回精确分数，以及标明是否精确的十进制结果。
- `unit` 只是调用方给出的单位标签，不执行单位换算，也不保证输入前提、主体或自然语言解释正确。
- 每个持久机会最多四次计算尝试，包括被拒绝或失败的尝试；延后重评和重启不能重置该机会额度。
- 计算单独计量，不消耗 Search/Fetch 的日额度或三次机会额度。调用模型选择工具及读取结果时，真实模型请求仍正常计数。
- 使用现有私有审计保存表达式、结果与状态。关键账本或审计失败时不能返回未记录的成功结果。

计算可以证明 `72 / 120 = 0.6`，不能证明剩余成员是否做过某个行为；结果正确也不能证明“每组”与“合计”用对了。最终正文仍需核对主体、分母、限定词及原始前提。十八项计算测试覆盖精度、非法语法、边界、错误、取消、私有审计失败与重启后的额度保持；自然语言事实正确性需要另外验收。

实现入口：`integrations/phase3_runtime/autonomy_arithmetic.py`；计数入口：`AutonomyState.reserve_calculation`。

R4另允许在已有私有 `content_check.calculations` 声明最多4个算式，由同一纯计算函数核对。精确值按分数比较；近似值必须显式声明0–6位舍入。它是有界CPU校验，不伪造FunctionTool调用、不重置四次工具账本，也不增加模型或联网调用。私有审计分别保存实际结果、相等判断、结果是否出现在正文，以及最终正文关联。中间结果可不出正文；空列表明确为未核算，不能声称所有自然语言算术都已验证。单位和实验前提仍需单独核对。

## 模型与工具计数边界

同 Agent 的草稿修订和工具续调继续走现有 Provider；每次实际 SDK 请求前写入持久预约与私有请求审计，回复只保存可见正文、工具调用和用量，不收集隐藏推理。SDK 必须关闭内部重试；本轮 Agent 不配置备用 Provider。额度耗尽、入站插话、夜间边界或审计不可用都会中止当前机会，不创建新机会来绕过额度。

每日模型、主动 Search/Fetch 与每机会工具额度仍使用原数据库记录。完成、失败、取消及未确认请求均保留计数；清理过期审计正文和研究口袋不删除调用账本、不补回额度。被动工具额度保持独立。内容修订中的语义判断仍是同 Agent 的判断，不能把结构化自查字段或正确引用片段当成整段内容的真实性证明。
