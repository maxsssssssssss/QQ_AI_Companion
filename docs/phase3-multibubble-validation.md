### 最小改动与固定依赖

继续使用 AstrBot 4.29.1、PrivateCompanion 6.7.0、MemoryCompanion 2.3.1、Recorder 0.0.4、NapCat 4.18.38。复用 Private 的 `<<PRIVATE_COMPANION_SPLIT>>`、`parse_llm_segment_control()` 和清理器；未升级组件、修改上游核心或收录第三方源码。

DeepSeek 在一次主模型生成中决定内容和气泡边界；一条足够就不分段。可选择 2–3 条，最多 4 条，不按句号、换行或字数切片，不强制追问。代码块、表格保守保持一条，保留原生清理后的文本。提示词在既有 V0.1 上补充分段协议，不替换人格；没有第二个分段模型或每气泡一次模型请求。

定位到的实际问题及修复：

1. Private 的后续清理会去掉分隔标记。Guard 先将原生解析结果变成普通 Plain 组件边界，最终只发送经全部清理器处理后仍存在的组件，不重新塞回原始模型文本。
2. 原生主动生成中的空白合并和控制标记清理会合并气泡。只在获准主动生成的 ContextVar 范围内，对原生解析后的各段继续调用原清理方法，再恢复语义边界；保留原有总长度限制，退出时恢复实例方法。不启用另一个发送器。
3. Guard 接管发送后，Private 留下的 `_no_save` 标志使已送达回复未进入下一轮模型历史。现在只在投影为已确认文本或固定未送达说明后解除标志，由 AstrBot 原有保存流程落库。完整联调已证明下一轮请求能读到两条已送达内容。

### 发送、打断与记录

首条在结果准备好后直接发送。后续间隔为 `min(1.8, 0.6 + 字符数/120)` 秒，无随机等待；每 0.1 秒检查取消、supersede 与停机。第一条仍须等待这一轮模型完成，未承诺流式首字送达。

每个气泡使用独立 delivery ID，复用 Guard 的发送方法及数据库；新增 `bubble_plans/bubble_parts` 仅存生成关联哈希、顺序、文本哈希、长度、尝试次数、状态和时间，不建立第二套正文库。实际尝试正文仍在既有 deliveries；未尝试气泡记 cancelled，失败为 failed，未能确认平台结果为 unknown，不重发整组、不在重启后补发。

模型历史只投影 confirmed sent 的文本，部分发送另加固定说明。Memory 的确认出站入口仍只接收已送达气泡，搜索进度不当作最终经历。平台 `sent` 表示适配器收到 API 确认，不代表对方已读；固定适配器丢弃平台 message_id 时仍为 null。

进程若在平台确认后、原生历史保存前突然退出，Guard 的持久记录仍在，但不保证该轮模型上下文已保存；不会把未发送正文自动重放。复杂输出图片/原生表情/引用保持组件归属，但本轮受控发送仅支持纯文本，复杂出站拒绝而不伪造成功。既有入站图片功能与此不同，新版真实图片回归仍按用户要求暂跳过。
