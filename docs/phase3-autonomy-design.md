# 小鲸自主主动聊天：第二阶段设计

本文保留第二阶段首轮设计。2026-10-29收尾后的实际规则与已上线版本见[收尾报告](phase3-autonomy-closeout.md)：同交流补充采用独立短避让；研究进展续期与资料时效分开。下表中的普通空闲门槛和默认三天口袋描述属于首轮历史，不代表最新规则。

开发基线为 `20783a0`，保留其90分钟／96次评估机会／12轮发送尝试。`d64b856`仅用于旧行为对照。2026-10-27只读线上核对确认这些频率值已生效，当时 `proactive_autonomy`尚不存在；2026-10-28本专项已新增并启用，频率保持原值。本专项配置不会重复调整频率。

## 复用与依赖

继续固定AstrBot4.29.1、PrivateCompanion6.7.0、MemoryCompanion2.3.1及当前NapCat和Recorder。不改第三方源码，不增加Agent、模型或调度器。V0.4、Thinking Off、V4多气泡及Guard保持。

原生候选与轮询提供机会 → 第一方分别检查探索／发送权限 → 同一个原生Agent自主选题及Search/Fetch → 原生正文清理 → Guard逐泡确认 → 原生历史和已确认偏好观察。工具结果回到原Agent后才产生最终决定。冷却期间只探索，夜间和新入站会中止旧机会；已获取资料存入现有主动SQLite中的有限待分享记录。

普通随机候选即使带有原生合成`origin_event_id`也不等于外部事件。明确事件仍保留其时效与权限。开放机会不要求最近聊天、兴趣种子或实用价值；实际内容去重与候选／尝试幂等分别处理。

## 需求与首轮实施默认值

| 项目 | 实现约定 | 依据 |
|---|---|---|
| 日常发送90分钟／96机会／12轮／09–23 | 读取并保留现行配置 | 已有发布与本次核对 |
| 实际模型请求 | 144／日，SDK实际调用处持久记账 | 本轮建议默认值 |
| 主动Search/Fetch | 288／日、3／机会，独立于被动60／日 | 本轮建议默认值 |
| 探索时长 | 每次最多600秒；同一机会不刷新3次工具额度 | 本轮需求及默认值 |
| 私有审计 | 14天、总量64MiB、单项2MiB；超限明确记录 | 14天为需求，容量为实施默认值 |
| 待分享口袋 | 最多64项有效记录，默认3天时效，来源／版本／进度可追溯 | 有界持久化为需求，容量及默认时效为实施值 |
| 延迟补充 | 同一交流最多一次、消耗一次发送尝试、更新冷却，不递归 | 本轮认可的首轮设计建议 |
| 补充机会窗口 | 确认发送后5–60分钟，经现有候选入口；保留普通空闲检查 | 实施默认值，不是用户曾指定的偏好 |

这些是上限和候选机会，不是发送或探索目标。兴趣表达本身正常消耗发送尝试；其后独立发送研究结果还需一次补充额度。一次Guard发送中的多气泡仍是一轮。

## 自身记忆接口

`NativeSelfPreferences`通过已有Guard observer唤醒现有worker，只读取确认送达的账本正文。调用原生偏好提取的最小部分，不调用整套发送后钩子、不重复写历史。游标与偏好同存原生用户记录，失败或unknown不成为已表达偏好；部分送达只观察确认部分。

当前原生能力限于五类显式偏好及有限条数，日常采用最新类别状态；不是完整观点修订库。`current()`／`prompt()`是后续并行自身记忆设计的薄接口。本轮不预填兴趣，不把未分享发现写成用户事实或稳定人格。

## 验证与发布

先验证确定性预算、恢复、插话、补充和固定原生链路，再执行独立的真实Flash与公开Search/Fetch实验。真实实验使用合成上下文、同一V0.4和Thinking Off，保留原始可见输出、实际SDK调用及Token；不使用生产次数或原10元验收预算伪造额度，也不向QQ批量发送。

发布必须经过一致备份、隔离恢复和源文件／配置基线核验，只重启AstrBot。功能总开关`proactive_autonomy.enabled`可关闭新路径，旧原生适配继续可用；回滚仅还原本批代码及拥有的配置子树，保留新聊天、账本、自身偏好和研究数据。具体已执行结果另列验证报告，设计不代表已部署或真实自然度通过。
