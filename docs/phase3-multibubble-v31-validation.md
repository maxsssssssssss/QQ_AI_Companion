## 规则与固定依赖

沿用 AstrBot 4.29.1、PrivateCompanion 6.7.0、NapCat 4.18.38、原生分段解析器和 Guard 发送链。有效 `<<PRIVATE_COMPANION_SPLIT>>` 优先；本轮不修改人格或分段提示词，不启用全局 segmented_reply，不新增模型或发送路径。

无标记普通闲聊的自动兜底改为：总长不超过 100 个 Python Unicode 字符（包括空格及 Emoji 组件）；2–4 个完整句子，以 `。！？!?` 识别句末；不要求固定开头。少于 6 个有效字母或数字（包括汉字，不计 Emoji、空格、标点）的句子向相邻句合并，末尾短句向前合并。最终必须为 2–4 泡，否则完整单条。不按逗号、换行或固定字数截断。

代码、表格、列表、链接、引用、已识别技术解释及复杂消息不参与兜底。搜索 progress/final 继续排除自动兜底；final 的有效模型标记仍使用原生解析。独立开关 `phase3_casual_split_fallback_enabled` 保留，默认关闭。后续气泡默认间隔 1–2 秒；首条没有附加延迟。现有已保存配置优先于默认值，未来启用必须明确合并配置，不能认为修改默认值就已改变线上间隔。

## 清理兼容契约

1. Guard 的早期 `on_llm_response` 只读分析原始模型输出，记录资格、长度、不可逆 SHA256 及合并后候选切点；不保存可恢复的回复副本。
2. 原生插件继续清理或拦截正文。Guard 不改固定版 Private 源码，也不把早期文本写回结果。
3. 最终文本与候选哈希完全一致时使用原切点。仅出现已确认的末尾中文 `。` 删除时允许映射切点，删除的句号保持删除。映射仅支持这个已知变体，不能概括为允许任意“格式变化”。
4. 其他正文改写、首尾 trim、CRLF 转换、无法验证的差异，均放弃自动兜底。非空正文继续现有单条路径；空结果、拦截、已取消或 supersede 不恢复回复。
5. 每个切片都来自最终允许发送的文本，发送前强制验证 `''.join(bubbles) == final_cleaned_text`。切片后不再逐片 strip，也不恢复原始标点。

模型标记仍由原生解析器处理；兜底异常只降级完整单条。逐条 ledger、确认依据、失败/unknown 停止、取消尾部、重启不重发及仅确认正文进入模型历史保持。历史在气泡间插入既有分隔换行，不能把历史分隔符误认为发送时丢字或补字。

诊断沿用 turn_id：原始候选数、实际选择、`candidate_exact` / `candidate_terminal_period_removed` / 拒绝原因、计划数及确认数。诊断不包含私人正文，资格与切点为本轮临时数据，不增加持久历史库。
