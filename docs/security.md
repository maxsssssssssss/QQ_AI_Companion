# Phase 1 安全与数据边界

本轮只处理合成 QQ 身份、合成文本/图片夹具和测试凭据。安全检查覆盖当前离线验收配置，不代表真实 QQ 运营或第三方插件的完整安全审计。最终测试状态及证据见 [Phase 1 验收报告](phase1-validation.md)。

## 网络与进程隔离

运行容器使用 `--network none`，只有 loopback。模拟 OneBot 和 Mock LLM 与真实 AstrBot 位于同一容器，分别监听 `127.0.0.1:6199` 和 `127.0.0.1:18080`；不发布宿主端口。服务本身的 loopback 地址与容器出口限制同时生效，不能只凭配置里的 localhost 宣称离线隔离。

容器还使用只读根文件系统、非 root UID/GID、`--cap-drop ALL`、`no-new-privileges`、进程/内存/CPU 限额和受限 `/tmp`。项目与第三方源码只读挂载；可写挂载仅用于该次状态和证据。Docker socket 不进入容器，宿主 SSH 目录不挂载。构建阶段需要网络和本地 Docker 权限；容器运行隔离不等于宿主 Docker daemon 没有权限。

`config/offline.json` 关闭仪表盘、Web 搜索和主动工具能力，入口只加载受限 persona 的工具/技能配置。运行脚本清空代理变量，避免 loopback 请求走宿主代理。验收检查真实 UID、网卡、Linux capabilities、权限提升标记、源码只读状态、无 Docker socket、外部连接失败和仪表盘未监听。

任何改变网络模式、添加宿主目录挂载、开启仪表盘、启用真实 provider 或真实 QQ 的配置都超出该离线验收结论，需要独立范围和验证。

## 配置、身份与权限

配置校验在 AstrBot 初始化之前执行。离线 profile 只接受 loopback HTTP/OneBot 地址和以 `offline-fixture-` 标识的夹具凭据；默认没有管理员，启用白名单和会话隔离，管理员不能绕过白名单。插件测试单独启用白名单中的合成管理员，不使用真实账户。

OneBot 握手检查缺失 token、错误 token 与正确 token。合成凭据公开仅用于没有出口的夹具，不是生产密钥，不应复用到真实服务。`.env.example` 不包含真实密钥，且运行脚本不会自动 source；本地 `.env`、状态、数据库、备份和日志由 `.gitignore` 排除。

Message Recorder 固定版本的原始查询命令缺少管理员限制，且搜索不是按发起者会话过滤。本项目在接收消息前，通过 AstrBot 公开 `command_management.update_command_permission` 将 Recorder 命令设为管理员权限，保持第三方源码不变；验收需要用普通合成用户实际请求他人的记录并确认被拒绝。

MemoryCompanion 的原始管理子命令已有管理员权限；仍需分别检查有效命令权限和普通对话中的记忆作用域。PrivateCompanion 的普通用户命令范围不以名称或单次加载推断，当前只对实际执行的状态/昵称等行为给出结论，不宣称已完成全面权限审计。具体实测见[插件说明](plugins.md)。

## 会话、隐私与证据

会话隔离检查真实 LLM 请求的全部相关输入，确认不同私聊用户、私聊与群聊、群内不同用户和不同群的合成哨兵没有串入。Mock 回答“不知道”不能证明没有上下文泄漏；断言必须依据 provider 发出的请求。

原生会话历史、Recorder 入站记录、Memory 记忆和 guard 发送记录的责任不同。guard 在私聊原生白名单之后持久化原文与消息链；它不负责把所有插件的主动发送统一归档，也不构成通用隐私过滤层。Private 的主动目标、额度及外部能力在本次 profile 中关闭；Memory 的跨窗口/跨插件桥接关闭。

原始协议记录和 SQLite/JSON 可能包含完整合成消息，是验证链路的证据而非生产日志策略。项目只允许本轮合成数据进入验收证据；真实聊天内容、访问令牌和个人资料不得写入仓库。doctor 对常见凭据格式的扫描是启发式预检，只覆盖其检查范围，不能保证识别所有秘密。错误日志也不应记录真实凭据或原始异常响应体。

`export_data.py` 使用明确表/字段白名单导出合成聊天数据，去掉已知命名秘密字段并避免读取配置；自由文本没有自动秘密识别保证。即使导出成功，也不能把真实聊天数据当作已脱敏材料发布。输出拒绝覆盖，完整状态恢复仍需 ZIP 备份。

上游 checkout、`.runtime/`、完整运行状态和原始日志不跟踪。需要保存到项目的报告与证据摘要应明确 run ID、版本、命令退出码和真实验证范围；不把旧运行文件重新命名成当前成功证据。

## 发送状态与故障处理

guard 只在受支持的非流式、非分段、Plain 私聊回复路径中接管公开 `event.send`。成功回执记为 `sent`；明确发送异常记为 `failed`；超时、取消或重启中断记为 `unknown`。不能把“已有回复文本”“进入发送 hook”或“未抛出流水线异常”当成发送成功，更不能把 OneBot 回执当成真实 QQ 用户已读。

重复入站键在数据库中持久化，后续重复停止处理。这个机制防止相同事件重复生成/发送，但中断后不会自动重新处理。发送超时可能意味着对端已经接受消息，因此没有自动重发；复杂消息留给上游时也不假定成功。无生产补发机制、恰好一次保证或完整主动消息投递账本。

LLM 错误、超时、畸形响应和 OneBot 发送失败需要有明确失败证据，并验证之后的正常消息仍能通过真实链路。有限故障注入验证基本恢复能力，不等于长期可用性或生产服务等级承诺。

## 备份恢复

`scripts/backup.py` 的前提是所有状态写入者已经停止；工具不能代替进程管理来证明停机。备份应包含整个状态根目录，包括配置、数据库、WAL、插件数据和外置 persona，不能只复制一个正在写入的 `.db`。

备份 ZIP 提供 SHA-256 文件清单与 SQLite `integrity_check`。恢复拒绝不存在清单中的额外内容、缺失文件、重复 ZIP 条目、路径穿越、绝对路径、链接、校验和错误以及损坏数据库。恢复目标必须完全不存在；校验失败不覆盖现有数据。

哈希不提供签名认证或加密。备份保留完整状态及可能存在的本地第三方源码，不应公开发布，也不应用于传播授权不明的插件。恢复后通过独立进程和真实协议链路验证可用性；不要把“ZIP 解压成功”当成业务恢复成功。

## 许可证与外部边界

AstrBot 按固定上游许可复用；第三方各自的版本、授权冲突与缺失见 [依赖核查](dependencies.md)。没有项目 LICENSE 不能解释为开源授权。本项目只进行用户指定的原样本地评估，不修改、重新发布或打包授权不明的第三方代码。

本轮不登录真实 QQ、不部署 VPS、不使用真实用户隐私、不注入生产密钥、不启用 Phase 2。WebUI、真实 QQ/LLM、复杂主动陪伴、图片/语音与跨插件长期记忆的未验证行为，都应保持明确的未运行或受限状态。
