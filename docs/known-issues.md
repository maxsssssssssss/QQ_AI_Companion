# 已知限制与修复记录

## 本阶段确认的限制

1. **真实 QQ、真实 DeepSeek 与生产部署未执行。** 本轮仅网络隔离的 OneBot/模型模拟对端；不能证明 QQ 风控、登录态长期在线、模型中文质量或公网网络可用。
2. **授权边界。** MemoryCompanion、PrivateCompanion 未找到项目级许可证，只作原样本地依赖评估，不纳入本仓库源码或镜像分发。Recorder 的 LICENSE 为 GPLv3、README 却称 AGPL，分发前需澄清。NapCat/SnowLuma 属限制性许可，未来使用方式需重新核对。
3. **Recorder 不自动覆盖出站。** 实测入站、重复记录、重启与恢复；普通模型回复没有 bot sender 记录。本项目 Guard 补齐本阶段私聊非流式单段文本的入站、出站及准确发送状态。它不声称覆盖主动发送、工具发送、所有媒体和分段输出。超时状态为 `unknown`，不自动补发。
4. **连续消息不是严格 FIFO。** AstrBot 在会话锁前有异步处理，网络到达顺序可能与模型处理顺序不同。实际验证每条中文/Emoji输入恰好处理一次、上下文按实际处理顺序累积、最终原文/历史/回复完整，无丢失覆盖。本阶段未宣称完成防抖、自然消息合并或严格到达顺序保证。
5. **Future Tasks 一次性失败删除。** 原生定时一次任务在 `finally` 删除任务，即使执行失败；本轮5项真实调度测试确认该行为。未实现生产提醒补发或可靠送达，不将其算成可靠提醒通过。自然语言模型选择提醒工具未验证。
6. **DeepSeek 官方型号未在线确认。** 当前网络策略不含官方文档/API域名，`deepseek-flash`、`deepseek-v4-pro` 的当前有效性和价格未确认。已核查原生 Provider/Search/Fetch 源码，4项无密钥/无效输入测试不代表真实搜索成功。模板默认禁用且不填真实密钥。
7. **P1 记忆与陪伴范围。** Memory 的手工写入、检索、当前轮注入、双向时间线捕获已测；自动LLM抽取、embedding及长期记忆质量未测。Private 的昵称/状态/隔离/持久化已测；主动消息、虚构日程、外部桥接在测试配置关闭，没有长周期陪伴质量结论。共同加载和一次实际请求的上下文可观察，不等于所有桥接能力通过。
8. **WebUI 未做页面验收。** 上游自带管理后台与插件页面已核查；本阶段headless配置关闭监听，不公开端口，也未重新开发管理后台。
9. **上游离线后台告警。** AstrBot启动仍尝试下载渲染端点及模型元数据；在 `network=none` 下请求失败并写日志，文本链路可运行。未绕过网络隔离或修改上游；这些失败不能误算成外网访问成功。
10. **构建平台范围。** 验证 `linux/amd64`、Python 3.12；其他CPU/系统尚未验收。初次构建/获取外部源需要受许可的GitHub/PyPI/Docker网络，运行验收阶段无外网。

## 已修复的项目集成问题

- 将外部运行根加入 Python 模块路径，解决 `data.plugins` 导入失败。
- 兼容 AstrBot 写出的 UTF-8 BOM；将框架不保留的项目元数据放到独立 `phase1.json` 侧车，真实重启验证。
- 停机前等待真实数据库提交，避免刚收到发送确认就中断仍在持久化的流水线。备份只在写入者已停止时执行。
- 不用上游 `after_message_sent` 钩子判成功，因为该钩子在失败后也可能触发；公开 `event.send()` 的结果进入最小发送状态表。
- 在其他插件业务前持久去重，防止相同ID再次触发模型和记录。
- Recorder 查询命令原本能跨用户查询，通过 AstrBot 公开命令权限API收紧为管理员；真实非管理员负例通过。
- 固定兼容依赖及只读镜像源码权限；未修改任何第三方源文件。早期诊断记录保留在本机 `evidence/runs/`，最终报告只引用最终选定运行，并如实保留上述P1缺口。

解除生产阻塞需要：明确插件/协议端使用与分发授权、核实官方API、获得进入Phase2的用户指令，并执行文档中的首次真实联调。Phase1 PASS（若最终P0全绿）不等同生产可直接上线。
