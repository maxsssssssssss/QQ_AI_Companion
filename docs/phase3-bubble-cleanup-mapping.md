## 原因与最小改动

两例真实反馈的原始模型输出均无分段标记，V3.1 只读分析均得到两个候选气泡。固定 PrivateCompanion 6.7.0 的 `llm_tool_actions.py::_extract_reaction_expression_hidden_intent` 会删除行尾 ASCII 空格/制表符，即使正文没有隐藏标签；`helpers.py::_strip_terminal_sentence_period` 还会删除末尾中文句号。原 Guard 只接受原文哈希或仅末尾句号删除，未识别行尾空白清理，故退回单条。线上两例均为计划一条、确认一条，发送与历史一致，不是第二泡发送失败。

使用用户已提供正文的有限变体核对原始 SHA256，并离线调用固定原生清理函数，精确复现 58→57 和 56→54 字符的变化。公共报告及测试不保存这两例私聊正文。诊断证据保留于私有 `evidence/phase3/proactive-boundary-audit-20261025/bubble-two-cases*.json`。

修复只扩展清理前的候选元数据：新增行尾 ASCII 空格/制表符删除及其与末尾中文句号删除的组合哈希与切点。仍不保留原始正文，仍只从最终允许发送的文本切片，严格校验 `''.join(parts) == final_cleaned_text`；不得恢复已删除空格或标点。任意正文改写、未知空白转换、空结果或拦截继续尊重原生结果，不重新评估改写后的文本资格。

有效模型标记、固定原生解析器、≤100字符、2–4句/泡、短句合并、技术与结构排除、独立 fallback 开关、搜索 progress/final 排除均不变。沿用 Guard 发送、1–2秒间隔、插话取消、确认与账本；显示边界 CR/LF 清理仍在切片完整性校验之后、账本登记之前执行。

诊断新增映射原因及 `first_fallback_rejection`：同轮第一次因正文不匹配或缺少候选而退出的原因不会被后续“候选不可用”覆盖。只记录枚举，不记录私人正文；每个新模型响应重置，避免带入后续响应。
